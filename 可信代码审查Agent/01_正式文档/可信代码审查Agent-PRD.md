# 可信代码审查 Agent · 产品需求文档

> 把「AI 生成评论」做成可核验、可处理、可回滚的审查单元。
> 这份文档说明它解决什么问题、边界在哪、以及每个判断的依据。

- 范围：MVP · 只读审查 + 审批后修复
- 角色：代码作者 / Reviewer / 平台管理员
- 状态：原型已验证，待试点
- 版本：v1.0 · 2026.11

## 摘要

| | |
|---|---|
| **问题** | 合入前的审查依赖人工：等待长、判断不可复核、低风险问题消耗高工 |
| **方案** | 六阶段流水线：接入 → 分析 → 发现 → 修复 → 验证 → 结论，每步留下证据 |
| **结果** | Precision 82.0%、Recall 51.2%，124 条标注全部判分，高危 4/4 召回 |
| **边界** | 默认不阻断合并；补丁只读预览；管理员不读业务内容 |

## 01 背景与问题

使用 PR 流程的团队，合入前的审查环节依赖人工 Reviewer。三个结构性痛点：

- **审查时间与开发节奏错位。** 作者被阻塞，Reviewer 被打断。
- **低风险问题消耗高级工程师注意力。** 命名、日志、注释类问题占掉大半时间。
- **评论缺少可复现证据。** 作者不信，Reviewer 也无法回溯当时的判断。

产品机会不是再接入一个模型入口，而是把每个高风险问题变成可核验、可处理、可回滚的决策单元。

## 02 目标与非目标

| 类型 | 内容 |
|---|---|
| 目标 | 审查结果可复核：每条发现带文件、行号、代码片段与验证结论 |
| 目标 | 审查过程可处理：确认 / 忽略 / 修复 / 验证都有明确动作与去处 |
| 目标 | 结论默认不阻断：先让人愿意看，再谈自动化 |
| 非目标 | 不做全自动合入，不替代 Reviewer 的判断 |
| 非目标 | 不追求覆盖率数字，不把低置信度发现包装成结论 |
| 非目标 | MVP 不做多租户计费与私有化部署 |

## 07 规则与放行

默认不阻断：未命中规则时结论自动通过，命中才进入待放行。

| 规则 | 条件 | 结果 |
|---|---|---|
| R1 | 存在未忽略的高危发现 | 待人工放行 |
| R2 | 变更超过 500 行 | 待人工放行 |
| R3 | 首次接入该仓库 | 待人工放行 |
| R4 | 低置信度发现 | 只记录，不阻断 |

![C02 放行判定流程](/docs/code-review-agent/figures/12_C02_放行判定流程.png)

*图 C02 · 放行判定流程。*

放行动作有前置条件：六个阶段未走完时，按钮保持禁用并说明原因。

## 09 非功能与风险

- **时延：** 单次审查 P95 控制在 5 分钟内，超时给出可重试的明确状态。
- **隔离：** Worker 不落业务代码，只保留 diff 片段与证据。
- **审计：** 放行、阻断、规则变更、补丁应用全部留痕，管理员只读。
- **风险：** 模型误报导致信任流失 —— 用默认不阻断与证据链兜底，而非提高阈值。

## 10 里程碑

| 阶段 | 交付 | 验证方式 |
|---|---|---|
| M1 只读审查 | 六阶段流水线 + 证据链 | 124 条标注集判分 |
| M2 处理闭环 | 确认 / 忽略 / 补丁 / 验证 | 端到端 5 个演示任务 |
| M3 治理 | 规则集、权限矩阵、审计 | 越界用例全部被拒 |
| M4 试点 | 单仓库灰度 | 放行率与误报反馈 |
