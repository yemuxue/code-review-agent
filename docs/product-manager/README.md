# AI 代码审查 Agent 产品经理作品集

本目录把 `code-review-agent` 从工程项目组织为产品材料。主线不是“展示做了多少代码”，而是证明能够完成从问题定义、用户研究、方案设计、评估闭环到商业化落地的完整产品工作。

文档中的 Mermaid 流程图、状态机、指标树、竞品定位图和路线图可直接在 GitHub Markdown 中查看；它们分别用于说明产品闭环、用户路径、系统边界、质量口径、竞品机会和交付依赖。

## 项目一句话定位

面向使用 GitHub/GitLab 协作的研发团队，提供“有证据、可解释、可控修复”的 AI 代码审查 Agent，帮助代码作者在合并前更早发现高风险问题，并减少人工审查中的重复劳动。

## 使用边界

- 文档中的“已有事实”来自仓库实现、测试与报告，例如 `docs/architecture.md`、`docs/agent-evaluation-plan.md`、`reports/` 和 `tests/`。
- 文档中的“待验证假设”使用明确标签标注，不能包装成真实客户结论。
- 竞品能力会随版本变化；本材料用于产品思考框架，正式对外引用前应补充访问日期、价格页面和实际试用记录。
- 当前项目是本地/自托管技术原型。PRD 中涉及 GitHub/GitLab 集成、团队协作和商业化的部分属于产品化规划，不代表已经实现。

## 建议阅读顺序

先阅读 `00` 了解事实边界，再打开 `01` 解释为什么这样定义需求；通过 `03` 查看行业与竞品判断，通过 `04` 查看落地方案，通过 `05` 查看效果证明，最后用 `02` 追溯研究结论如何从假设中产生。

## 完善标准

- 每个需求都有用户、场景、价值、风险和验收条件。
- 每个指标都有定义、分子、分母、切片和决策用途。
- 每个竞品判断都有实测计划，不把公开功能描述当成真实质量结论。
- 每个研究洞察都区分事实、观察和待验证假设。
- 每个图示都服务一个产品决策，不用装饰性图形代替证据。
